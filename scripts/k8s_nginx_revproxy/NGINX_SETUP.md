# nginx setup — tuned & hardened for the reverse proxy (Debian 12)

Step-by-step install and hardening of nginx on a Debian 12 host that will front
the Kubernetes NodePort services generated by
[`k8s_nginx_revproxy.py`](k8s_nginx_revproxy.py). All TLS and hardening settings
are kept **global** (in `http {}`), so the vhosts this tool auto-generates inherit
them and stay minimal.

> Assumes a wildcard TLS certificate and a wildcard DNS record for
> `*.PROXY_DOMAIN` already exist (see the main [README](README.md)).

## 1. Patch the base system and enable automatic security updates

```bash
sudo apt update && sudo apt -y full-upgrade
sudo apt -y install unattended-upgrades
sudo dpkg-reconfigure -plow unattended-upgrades
```

Keeping nginx and OpenSSL patched automatically is the single most important
control for an internet-facing proxy.

## 2. Install nginx

Debian 12 ships nginx 1.22 with backported security fixes — lowest maintenance:

```bash
sudo apt -y install nginx
```

If you want the latest stable (1.26+), use the official nginx.org repo instead:

```bash
sudo apt -y install curl gnupg2 ca-certificates lsb-release debian-archive-keyring
curl -fsSL https://nginx.org/keys/nginx_signing.key | sudo gpg --dearmor -o /usr/share/keyrings/nginx-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/nginx-archive-keyring.gpg] http://nginx.org/packages/debian bookworm nginx" | sudo tee /etc/apt/sources.list.d/nginx.list
sudo apt update && sudo apt -y install nginx
```

Either works with the rest of this guide.

## 3. Firewall — expose only 80/443 (and SSH)

```bash
sudo apt -y install ufw
sudo ufw allow OpenSSH
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw --force enable
```

> Make sure SSH is allowed **before** enabling, or you will lock yourself out.

## 4. Wire in the auto-generated vhost directory

The daemon writes vhosts into `/etc/nginx/k8s-revproxy/` (its `--output-dir`).

```bash
sudo mkdir -p /etc/nginx/k8s-revproxy
sudo chmod 755 /etc/nginx/k8s-revproxy
```

Add this line inside the `http { ... }` block of `/etc/nginx/nginx.conf`:

```nginx
include /etc/nginx/k8s-revproxy/*.conf;
```

This is where the daemon's `00-maps.conf` (the websocket `map`, which must live
in `http{}` context) and each `<port>-<service>.<domain>.conf` land.

## 5. Global hardening snippet

Debian's `nginx.conf` auto-includes `/etc/nginx/conf.d/*.conf`. Create
`/etc/nginx/conf.d/00-hardening.conf`:

```nginx
# --- Information disclosure ---
server_tokens off;                 # hide nginx version in headers/error pages

# --- Long generated hostnames need a bigger server-name hash bucket ---
server_names_hash_bucket_size 128;

# --- Request size / slow-loris protection ---
client_max_body_size        50m;   # raise per-service if you proxy uploads
client_body_timeout         10s;
client_header_timeout       10s;
send_timeout                10s;
keepalive_timeout           65s;
client_body_buffer_size     16k;
client_header_buffer_size   1k;
large_client_header_buffers 4 8k;

# --- Security response headers (inherited by all vhosts) ---
add_header X-Content-Type-Options    "nosniff"                          always;
add_header X-Frame-Options           "SAMEORIGIN"                       always;
add_header Referrer-Policy           "strict-origin-when-cross-origin"  always;
add_header Strict-Transport-Security "max-age=63072000; includeSubDomains" always;

# --- Rate-limiting zones (apply per-vhost with `limit_req zone=...` if needed) ---
limit_req_zone  $binary_remote_addr zone=req_per_ip:10m rate=20r/s;
limit_conn_zone $binary_remote_addr zone=conn_per_ip:10m;
```

The generated vhosts set no `add_header` of their own, so these headers
propagate to every proxied response.

> `server_names_hash_bucket_size 128;` covers hostnames up to ~127 chars. Without
> it nginx fails with *"could not build server_names_hash"* once you have several
> long vhosts. Bump to `256` if you ever generate longer names.

## 6. TLS hardening snippet

Create `/etc/nginx/conf.d/10-tls.conf` (Mozilla "intermediate" — TLS 1.2 + 1.3):

```nginx
ssl_protocols             TLSv1.2 TLSv1.3;
ssl_prefer_server_ciphers off;
ssl_ciphers               ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-ECDSA-CHACHA20-POLY1305:ECDHE-RSA-CHACHA20-POLY1305:DHE-RSA-AES128-GCM-SHA256:DHE-RSA-AES256-GCM-SHA384;

ssl_session_timeout  1d;
ssl_session_cache    shared:MozSSL:10m;   # ~40,000 sessions
ssl_session_tickets  off;

ssl_dhparam /etc/nginx/dhparam.pem;

# OCSP stapling (works with a public wildcard CA)
ssl_stapling         on;
ssl_stapling_verify  on;
resolver             1.1.1.1 9.9.9.9 valid=300s;
resolver_timeout     5s;
```

Generate the DH params once (takes a minute):

```bash
sudo openssl dhparam -out /etc/nginx/dhparam.pem 2048
```

These global settings mean the generated vhosts only need `ssl_certificate` /
`ssl_certificate_key` (which the daemon writes) — protocols, ciphers, and
stapling are inherited.

## 7. Default "deny unknown host" server

Critical for a reverse proxy: without it, nginx serves the *first* vhost to any
request hitting the raw IP or a bogus `Host` header. Add a catch-all that drops
them. Create `/etc/nginx/conf.d/05-default-server.conf`:

```nginx
server {
    listen 80  default_server;
    listen [::]:80 default_server;
    listen 443 ssl http2 default_server;
    listen [::]:443 ssl http2 default_server;
    server_name _;

    ssl_certificate     /etc/letsencrypt/live/PROXY_DOMAIN/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/PROXY_DOMAIN/privkey.pem;

    return 444;   # close the connection without a response
}
```

Only explicitly-matched hostnames (the generated `<port>-<service>.<domain>`
vhosts) get served; everything else is dropped. Remove Debian's default site so
it doesn't also claim `default_server`:

```bash
sudo rm -f /etc/nginx/sites-enabled/default
```

## 8. Lock down the certificate key permissions

```bash
sudo chmod 600 /etc/ssl/private/wildcard.key   # or the letsencrypt privkey.pem
sudo chown root:root /etc/ssl/private/wildcard.key
```

nginx reads certs as the master process (root); workers never need access.

## 9. Harden the nginx systemd service

Add sandboxing without editing the packaged unit:

```bash
sudo systemctl edit nginx
```

Paste into the override editor and save:

```ini
[Service]
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ProtectHome=true
# '-' makes a missing path non-fatal (avoids 226/NAMESPACE start failures).
ReadWritePaths=-/var/log/nginx -/var/lib/nginx -/var/cache/nginx -/run
ProtectKernelTunables=true
ProtectKernelModules=true
ProtectControlGroups=true
RestrictAddressFamilies=AF_INET AF_INET6 AF_UNIX
RestrictNamespaces=true
```

> The `-` prefix matters: some builds don't create `/var/cache/nginx`, and
> `ProtectSystem=strict` aborts namespace setup (`status=226/NAMESPACE`,
> *"Failed to set up mount namespacing … No such file or directory"*) on any
> missing `ReadWritePaths` entry. The `-` makes those optional.

`ProtectSystem=strict` keeps `/etc/nginx` read-only for nginx, which is fine —
the daemon (not nginx) writes the vhost files and then triggers `nginx -t` /
reload.

## 10. Test, reload, enable

```bash
sudo systemctl daemon-reload
sudo nginx -t
sudo systemctl enable --now nginx
sudo systemctl restart nginx
```

`nginx -t` must pass before restart — the same gate the daemon uses before
reloading, so the two stay consistent.

## 11. Verify

Check the effective TLS + headers against one of the generated hostnames:

```bash
curl -sSI https://<port>-<service>.PROXY_DOMAIN | grep -iE 'strict-transport|x-frame|x-content|server'
nmap --script ssl-enum-ciphers -p 443 PROXY_DOMAIN
```

For an external grade, run the host through SSL Labs
(`https://www.ssllabs.com/ssltest/`) or `testssl.sh`.

## Optional next layers

- **fail2ban** for the SSH/HTTP surface: `sudo apt -y install fail2ban`
  (enable the `sshd` and `nginx-*` jails).
- **Per-vhost rate limiting** — apply the zones from step 5 with
  `limit_req zone=req_per_ip burst=40 nodelay;`. Since the generated `location`
  blocks are fixed, add it to the script's vhost template if you want it applied
  automatically.
- **ModSecurity + OWASP CRS** if you need a WAF in front of the proxied apps
  (heavier; only if the threat model calls for it).

## Notes specific to this reverse proxy

- The daemon owns `/etc/nginx/k8s-revproxy/*.conf`. Everything in this guide
  lives in files *you* manage (`conf.d/*.conf`, `nginx.conf`), so the daemon's
  rollback logic never touches your hardening.
- HTTP/2 is enabled via the `listen … ssl http2;` parameter form, which works on
  Debian's nginx 1.22 (the separate `http2 on;` directive is 1.25.1+ only).
- Only TCP services are proxied; UDP/SCTP NodePorts are skipped by the daemon.

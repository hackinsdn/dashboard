# Internationalization (i18n)

The dashboard UI is translated with [Flask-Babel](https://python-babel.github.io/flask-babel/).
Currently supported locales: **English (`en`, default)** and **Portuguese – Brazil (`pt_BR`)**.

## How it works

- **Config** ([apps/config.py](../apps/config.py)): `LANGUAGES`, `BABEL_DEFAULT_LOCALE`,
  `BABEL_DEFAULT_TIMEZONE`, `BABEL_TRANSLATION_DIRECTORIES`. All overridable via env vars.
- **Extension** ([apps/__init__.py](../apps/__init__.py)): `babel.init_app(app, locale_selector=select_locale)`.
- **Locale resolution order** (`select_locale`):
  1. explicit choice stored in `session["locale"]` (set via the navbar switcher),
  2. the authenticated user's `Users.locale` column,
  3. the browser `Accept-Language` header,
  4. `BABEL_DEFAULT_LOCALE`.
- **Switcher UI**: globe dropdown in [apps/templates/includes/navigation.html](../apps/templates/includes/navigation.html),
  posting to the `home_blueprint.set_locale` route which persists the choice.
- **Catalogs** live in `apps/translations/<lang>/LC_MESSAGES/messages.po` (+ compiled `.mo`).

## Marking strings for translation

**Templates** — wrap literals in `_()`:

```jinja
<p>{{ _('Dashboard') }}</p>
{{ form.password(placeholder=_("Password")) }}
{% trans user=current_user.username %}Welcome, {{ user }}{% endtrans %}
```

**Python (forms, request handlers)**:

```python
from flask_babel import gettext as _, lazy_gettext as _l
# module level / form definitions (evaluated at import time) -> lazy
name = StringField(_l('Group Name'))
# inside a request -> gettext
return jsonify({"error": _("Lab not found")}), 404
```

Do **not** wrap log messages or internal/machine strings.

## Updating translations

After adding or changing strings (requires `pip install flask-babel`, which provides `pybabel`):

```bash
make i18n-update     # re-extract + merge new strings into every language .po
make i18n-ptbr       # apply the pt_BR master table; lists anything still missing
make i18n-compile    # build the .mo files the app loads
```

`make i18n-update` uses `--no-fuzzy-matching` on purpose: without it, `pybabel
update` auto-fills each new string from a *similar-looking* existing
translation (e.g. `Color` → `Limpar`), which is almost always wrong and easy to
miss because the entry then looks "translated".

pt_BR translations live in a single source-of-truth table,
[scripts/i18n_ptbr.py](../scripts/i18n_ptbr.py), rather than being hand-edited
into the `.po`. Add new strings there and re-run `make i18n-ptbr` — it also
clears any stale `fuzzy` flags. For other languages, edit the `.po` directly.

Add a new language:

```bash
make i18n-init LANG=es
make i18n-compile
```

The compiled `.mo` files are committed and are also rebuilt during the Docker
image build (`pybabel compile` step in the [Dockerfile](../Dockerfile)), so a
running container always has up-to-date catalogs.

## Scope / not covered

Only the UI chrome is translated. **DB-authored content** (lab titles, descriptions,
guides, questions/answers) is user-generated and is not handled by Flask-Babel —
translating it would require per-record storage and is a separate effort.
